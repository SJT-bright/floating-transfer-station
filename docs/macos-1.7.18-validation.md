# macOS 1.7.18 图片多选与缺失素材记录保护验证

日期：2026-10-11。Windows 本次没有变更。

## 交互与数据契约

图片卡片在图钉左侧提供独立勾选框。勾选立即显示蓝色勾和卡片亮边；列表底部显示已选数量、取消选择，不移动上方勾选区域。文字、文件卡片布局不变，标题仍可直接改名。

拖动已勾选图片使用全部已选图片，按置顶分区与显示顺序生成多个原生拖放项目；拖动未勾选图片只发送自身。分页保留同分类选择，切换分类、重启清除选择，删除或容量淘汰会移除失效选择。勾选不写入看板数据。

每个拖放项目提供自身原始 PNG、持久兼容文件地址与站内标识，图片字节不重新编码。专用后台队列准备图片，不等待文件导入队列。准备结束前松开鼠标或源图片被删除时不启动过期拖放。站内分类接收整批图片，一次原子保存独立副本、保留源图、按批内顺序插入普通区，成功只提示一次；复制或保存失败回滚整批。

- 图片传输回归：7 项通过，包括多选点击顺序不影响拖出顺序、未选项单独拖动、多个原生剪贴板项目、逐图原 PNG/ICC/元数据与文件地址一致、站内批量保存、源图与置顶不变、选择清理，以及缺图和保存失败的整批回滚。
- 性能检查：1,800 条内容、30 次重开约 3.78 秒；预览保留原 PNG 与 Display P3，重复窗口通知不反复刷新。

## 真实界面检查

使用独立测试数据和独立剪贴板，不采集或修改正式素材。实际点击确认两张图片同时显示已选、数量为 2；观察截图确认勾选框位于图钉左侧。确认取消全部、切换分类清除选择；关闭复制/置顶快捷按钮后，多选框仍可勾选。

原生拖放的鼠标按下链路尚未完成实机验收：当前界面自动操作工具尝试拖动后没有产生拖放结果。不能把原生剪贴板契约测试算作浏览器真实接收通过。最终还需普通鼠标在支持多文件上传的浏览器页面和站内分类各拖一次，核对数量、顺序与原图。

## 更新时发现的旧加载问题

正式应用重启后显示 45 条，而磁盘看板及更新前备份均有 107 条；更新前后整个数据目录字节一致。排查发现 60 张图片与 2 个文件已经缺失，旧加载器过滤这些引用，并会在下次保存时丢掉对应元数据。1.7.18 改为保留安全站内路径的缺失素材记录、显示缺失提示；不恢复用户主动删除的旧记录，不伪造原文件，不放宽路径边界。
